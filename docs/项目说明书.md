# 项目说明书

## 1. 需求分析
- **服务对象**：寻找兼职、远程办公或开源项目机会的开发者及求职者。
- **核心痛点**：
  1. 招聘网站信息繁杂，切换成本高。
  2. 优质开源社区（如 GitHub）的岗位多为英文，存在语言门槛。
  3. 传统抓取工具容易因网络波动或接口限流导致程序崩溃。
- **解决方案**：开发一套集“真实数据采集、NLP 并发自动翻译、数据可视化、专业报表导出”于一体的 Web 软件系统。

## 2. 系统架构设计（分层架构）
- **数据层（database.py）**：采用轻量级 SQLite 数据库。设计了 `jobs` 业务表（中英双语字段）与 `config` 配置表（记录爬虫游标，支持断点续爬与翻页叠加）。使用唯一索引实现幂等去重。
- **业务层（spider.py）**：核心爬虫模块。负责与 GitHub 官方 API 通信，并集成了多线程并发翻译引擎与异常降级处理逻辑。
- **控制层（app.py）**：Flask 后端。负责路由分发、请求参数校验以及基于 `openpyxl` 的高阶 Excel 导出。
- **展示层（index.html）**：企业级后台管理风格。集成 ECharts 实现数据可视化，并内置了前端字典映射与浏览器翻译引导机制。

## 3. 核心工程难点与解决方案（重点）

### 3.1 性能优化：串行翻译导致的等待过长
- **现象**：初期采用单线程逐个调用翻译 API，抓取 30 条数据需等待近 30 秒，用户体验极差。
- **解决方案**：重构爬虫代码，引入 Python 的 `concurrent.futures.ThreadPoolExecutor` 线程池技术。将翻译任务并发化（`max_workers=10`），将 30 条数据的清洗总耗时压缩至 3 秒以内，同时移除了单线程下的强制休眠逻辑，大幅提升抓取效率。

### 3.2 频控保护：第三方 API 限流与网络波动
- **现象**：连续翻页抓取时，触发 GitHub 匿名 API 的频率限制或翻页深度限制（Rate Limit），导致返回空数据。
- **解决方案**：系统构建了完善的 `try...except` 容错闭环。当触发限制或网络超时，程序不会崩溃，而是自动捕获异常，并通过 URL 参数将 `⚠️ 本次未抓到新数据，或网络受限` 的友好提示回传至前端展示。同时，业务逻辑支持通过动态修改搜索关键词（如 `freelance`）来突破单一标签的数据枯竭瓶颈，保证了系统的鲁棒性。

### 3.3 数据质量：机翻生硬与图表标签溢出
- **现象**：机器翻译长仓库名时容易产生生硬结果，且 ECharts 图表因数据量过大导致标签严重重叠。
- **解决方案**：
  1. 在后端为翻译接口设置 5 秒超时与“降级保存原文”机制。
  2. 在前端实现“Top 10 排序截取”、“本地化字典映射（将高频英文映射为中文）”与“超长文本截断”，确保表格和图表数据展示的统一与美观。

## 4. 功能说明
- **增量真实采集**：每次点击抓取自动获取下一页 30 条全新数据，结合数据库幂等去重实现数据叠加。
- **多条件检索**：SQL 层面支持按英文名、中文翻译、公司名进行模糊查询。
- **专业级 Excel 导出**：告别简陋的 CSV，采用 `openpyxl` 生成 `.xlsx`，实现了微软雅黑字体、表头高亮、自适应列宽与长文本自动换行。

## 5. 依赖环境与运行方式
- **环境要求**：Python 3.8+
- **依赖清单**：详见根目录 `requirements.txt`（包含 Flask, requests, openpyxl 等）。
- **运行命令**：
  1. 安装依赖：`pip install -r requirements.txt`
  2. **进入源码目录**：`cd src`
  3. 启动服务：`python app.py`
  4. 浏览器访问：`http://127.0.0.1:5000`
